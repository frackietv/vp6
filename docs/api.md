# VP6 API reference

Everything a VP6 program can use after:

```python
from vp6 import *
```

The API follows Visual Basic 6 naming: PascalCase properties and methods
(`Caption`, `Show()`), event handlers named `Object_Event`, and constants
with a `vp` prefix (VB's `vbYes` is `vpYes`). Positions and sizes are in
**pixels**.

The property tables below are generated from the controls' own metadata
(`Properties` / `PropSpec` in `vp6/controls.py` and `vp6/form.py`). They list
exactly what the Properties window shows and what the designer writes.

## 1. Program structure

### Forms

A form is a subclass of `Form`. Controls are created in
`InitializeComponent`, normally written by the IDE designer:

```python
from vp6 import *


class Form1(Form):
    # region VP6 Designer - generated by the form designer, do not edit
    def InitializeComponent(self):
        self.Caption = 'Greeter'
        self.txtName = TextBox(self, Text='', Left=16, Top=16, Width=160, Height=25)
        self.cmdGreet = CommandButton(self, Caption='&Greet', Left=184, Top=12, Default=True)
    # endregion

    def cmdGreet_Click(self):
        MsgBox(f"Hello, {self.txtName.Text}!", vpInformation)


if __name__ == "__main__":
    run(Form1)
```

* A control's first argument is its container: the form (`self`) or a
  `Frame` / `PictureBox` (`self.Frame1`). The remaining keyword arguments set
  properties.
* Assigning the control to an attribute names it: `self.cmdGreet = ...`
  gives the control the `Name` `"cmdGreet"`, which is what event handler
  names refer to.
* You can also create controls in code at run time, e.g. in `Form_Load`, the
  same way.
* Controls can share a name as a [control array](#control-arrays):
  `self.cmdDigit = ControlArray()`, then `self.cmdDigit[0] = CommandButton(...)`.

### Modules and `Sub Main`

Any other `.py` file in the project is a module. A project whose startup
object is `Sub Main` calls the `Main()` function defined in one of its
modules. For a console project, `Main`'s return value (if an int) becomes the
exit code. A GUI project keeps running while any form is open after `Main`
returns.

```python
def Main():
    name = input("What is your name? ")
    print(f"Hello, {name}!")
```

## 2. Events

An event handler is a form method named `<ObjectName>_<Event>`. The form's
own events are `Form_<Event>`:

```python
def Form_Load(self): ...
def Command1_Click(self): ...
def Text1_KeyPress(self, KeyAscii): ...
def Picture1_MouseMove(self, Button, Shift, X, Y): ...
```

* **Parameters are optional.** A handler receives only as many arguments as
  it declares, so `def Picture1_MouseMove(self)` is fine too.
* **Handlers are looked up when the event fires,** so they can be attached at
  run time: `setattr(self, "Command1_Click", some_function)`.
* **Return values replace VB's `ByRef` arguments:**

  | Event | Return | Effect |
  |---|---|---|
  | `KeyPress(KeyAscii)` | `0` | the key is swallowed |
  | `KeyPress(KeyAscii)` | another int | the typed character is replaced, e.g. `return ord(chr(KeyAscii).upper())` |
  | `Form_KeyDown` / `Form_KeyUp` with `KeyPreview = True` | `0` | the key is cancelled |
  | `Form_Unload` | `True` | closing is cancelled (VB's `Cancel = 1`) |

* **Errors** in a handler show a *Run-time error* box (End / Continue). The
  traceback goes to stderr, i.e. the IDE's Immediate window.

### Event arguments

Handlers of a [control array](#control-arrays) get the element's `Index`
first, before the arguments below: `def cmdDigit_Click(self, Index)`,
`def cmdDigit_MouseDown(self, Index, Button, Shift, X, Y)`.

What the arguments mean:

* **`Button`** is `vpLeftButton` 1, `vpRightButton` 2 or `vpMiddleButton` 4 (a
  bitmask for `MouseMove`).
* **`Shift`** is a bitmask of `vpShiftMask` 1, `vpCtrlMask` 2 (⌘ on macOS)
  and `vpAltMask` 4.
* **`X`, `Y`** are pixels relative to the object.
* **`KeyCode`** is a `vpKey*` constant; **`KeyAscii`** is the character code.
* `Change` fires when TextBox/ComboBox text is edited or a scroll bar's value
  changes. `Scroll` fires while a scroll bar's thumb is dragged. `Timer`
  fires every `Interval` ms.
* `Load`, `Unload`, `Initialize`, `Activate`, `Deactivate` and `Resize` are
  form events.

## 4. Controls

### Members of every control

| Member | Description |
|---|---|
| `Name` | read-only; set by the attribute the control is assigned to (all elements of a control array share it) |
| `Index` | read-only; the element's number in a [control array](#control-arrays), `None` for other controls |
| `Parent`, `Container` | the form or container control the control is on |
| `SetFocus()` | gives the control the keyboard focus |
| `Move(Left, Top=None, Width=None, Height=None)` | moves / resizes |
| `Refresh()` | repaints |
| `ZOrder(Position=0)` | `0` brings to the front, `1` sends to the back, by setting `ZIndex` just above or below the other controls in the same container |

Setting a property that doesn't exist (e.g. `Command1.Captoin = "x"`) raises
`AttributeError`, like VB's error 438.

The "Default event" is what the designer opens when you double-click the
control.

**Stacking (`ZIndex`).** When controls overlap, the one with the higher
`ZIndex` is drawn on top.

* It applies among controls in the same container; a control inside a Frame
  is clipped to that Frame.
* Equal values keep creation order: controls created later are on top.
* Changing `ZIndex` at run time takes effect immediately:

  ```python
  self.Label1.ZIndex = 5          # now above siblings with lower values
  self.Label2.ZOrder(0)           # VB's method: bring to front (sets ZIndex)
  ```

The Timer, invisible at run time, has no `ZIndex`.

### Control arrays

Several controls of the same type can share a name, told apart by their
`Index`, like VB's control arrays. One handler serves them all and gets the
`Index` of the element that fired the event first. The designer writes
them like this (see [below](#control-arrays-in-the-designer) for how to make
one):

```python
self.cmdDigit = ControlArray()
self.cmdDigit[0] = CommandButton(self, Caption='0', Left=8, Top=8)
self.cmdDigit[1] = CommandButton(self, Caption='1', Left=56, Top=8)

def cmdDigit_Click(self, Index):
    self.txtDisplay.Text += self.cmdDigit[Index].Caption
```

`ControlArray` members:

| Member | Description |
|---|---|
| `array[i]`, `array(i)`, `Item(i)` | the element with Index `i` (`array(i)` is VB's syntax); `IndexError` if there is none |
| `for c in array` | the elements in Index order |
| `Count`, `len(array)` | the number of elements |
| `LBound`, `UBound` | the lowest and highest Index |
| `i in array` | whether there is an element `i` |
| `Load(i)` | adds element `i` at run time (VB's `Load cmdDigit(i)`, also `Load(self.cmdDigit, i)`) and returns it: a copy of the lowest element's properties, except that it's hidden (`Visible = False`, so position it and show it) and last in the tab order. It goes in the same container. |
| `Unload(i)` | removes element `i` (also `Unload(self.cmdDigit, i)`); only elements added with `Load` can be removed, others can be hidden |

* An `Index` is a whole number from 0 to 32767. Indexes needn't be
  contiguous.
* An element can be a container: `CheckBox(self.fraGroup[1], ...)`.
* `Index` is set in the designer (or by assigning to `array[i]`), not at run
  time.

#### Control arrays in the designer

* **Copy and paste** a control: VB's question *"You already have a control
  named 'Command1'. Do you want to create a control array?"* appears. *Yes*
  makes the original element 0 and the copy element 1; *No* gives the copy a
  new name. Pasting more copies of an array's element adds elements without
  asking.
* **Give a control the name of another control of the same type** in the
  Properties window: the same question, then it joins that control's array.
* **Set `Index`** in the Properties window (the row under `(Name)`): the
  control becomes a one-element array, or moves to another Index. Clearing
  `Index` of an array's only element makes it a plain control again.
* When a control becomes an array (or stops being one), its event handlers
  get the `Index` parameter added (or removed), as in VB. New handlers are
  created with it.
* The Properties window lists elements as `cmdDigit(0)`; the code window's
  Object list shows the array once.

## 5. Functions and global objects

### Dialogs

**`MsgBox(prompt, buttons=vpOKOnly, title=None) -> int`**

Shows a message box and returns the button pressed. Combine a button set, an
icon and a default button by adding constants:

```python
if MsgBox("Save changes?", vpYesNoCancel + vpQuestion + vpDefaultButton1) == vpYes:
    ...
```

| Part | Constants |
|---|---|
| Buttons | `vpOKOnly`, `vpOKCancel`, `vpAbortRetryIgnore`, `vpYesNoCancel`, `vpYesNo`, `vpRetryCancel` |
| Icon | `vpCritical`, `vpQuestion`, `vpExclamation`, `vpInformation` |
| Default button | `vpDefaultButton1`, `vpDefaultButton2`, `vpDefaultButton3` |
| Results | `vpOK`, `vpCancel`, `vpAbort`, `vpRetry`, `vpIgnore`, `vpYes`, `vpNo` |

Closing the box with Esc returns `vpCancel` when the box has a Cancel button.
The title defaults to `App.EXEName`.

**`InputBox(prompt, title=None, default="") -> str`**

Asks for a line of text. Returns `""` if cancelled.

Both dialogs take the light/dark scheme of the form they are shown over.

### Forms

| Name | Description |
|---|---|
| `run(form)` | Shows a form (class or instance) and runs the event loop until all windows close; returns the exit code. Put it under `if __name__ == "__main__":` to make a form runnable on its own. |
| `Load(form)` | `form.Load()` |
| `Load(array, Index)` | adds a [control array](#control-arrays) element at run time and returns it (`array.Load(Index)`) |
| `Unload(form)` | `form.Unload()`; returns `False` if cancelled |
| `Unload(array, Index)` | removes a control array element added with `Load` (`array.Unload(Index)`) |
| `Forms` | the loaded forms: `Forms.Count`, `len(Forms)`, `for f in Forms`, `Forms[0]` |

### Program control

| Name | Description |
|---|---|
| `DoEvents()` | processes pending GUI events (keep the UI alive in long loops) |
| `End()` | ends the program immediately; `Form_Unload` handlers do **not** run |
| Ctrl+C | Not a function, but part of how programs end. Pressed in the terminal that started a program, it closes the program's forms like their close buttons would: an open `MsgBox` or modal form closes first, each `Form_Unload` runs and may cancel, and the program ends when the last form is gone. A console program waiting at `input()` ends with exit code 130. |
| `Beep()` | system beep |

## 6. Colors

Colors are integers in VB's `&H00BBGGRR` (blue-green-red) order:

```python
self.BackColor = RGB(255, 255, 224)     # light yellow
self.Label1.ForeColor = vpRed           # == RGB(255, 0, 0) == 0x0000FF
self.Label2.ForeColor = "#336699"       # also accepted: '#RRGGBB' or a color name
self.Text1.BackColor = None             # back to the default color
```

| Name | Description |
|---|---|
| `RGB(red, green, blue)` | a color from 0-255 components |
| `QBColor(index)` | one of the 16 classic QuickBasic colors (0-15) |
| `vpBlack` `0x000000`, `vpRed` `0x0000FF`, `vpGreen` `0x00FF00`, `vpYellow` `0x00FFFF`, `vpBlue` `0xFF0000`, `vpMagenta` `0xFF00FF`, `vpCyan` `0xFFFF00`, `vpWhite` `0xFFFFFF` | color constants |

Reading a color property always returns the BGR int, or `None` for the
default.

## 7. Color schemes (light/dark)

A form's `ColorScheme` decides whether it looks light or dark. The project
file's `color_scheme` sets the default for forms left on Project Default.

| Value | Constant | Meaning |
|---|---|---|
| 0 | `vpSchemeProjectDefault` | use the project's scheme (`system`, `light`, `dark` or `ide`) |
| 1 | `vpSchemeSystem` | native look, follows the OS light/dark appearance live |
| 2 | `vpSchemeLight` | always light |
| 3 | `vpSchemeDark` | always dark |
| 4 | `vpSchemeIDE` | follow the VP6 IDE's light/dark setting. When run from the IDE, the setting at launch; when run on its own, System. |

* **The look of forced schemes.** Light and Dark use Qt's Fusion style with a
  fixed palette, because native styles (macOS) can't be forced per window.
  The OS still draws the window title bar in its own appearance.
* `BackColor` and `ForeColor` override the scheme's colors.
* When a form runs on its own (`python Form1.py`), Project Default is read
  from a `.vp6p` file in the same folder, if there is one.

The scheme can be changed at run time:

```python
self.ColorScheme = vpSchemeDark
```

## 9. Projects and running programs

A project folder contains the forms, the modules and a `Name.vp6p` project
file. The project file is an executable launcher script:

```bash
./Calculator.vp6p                                   # first python3 on PATH
VP6_PYTHON=/path/to/venv/bin/python ./Calculator.vp6p
python3 Calculator.vp6p                             # e.g. on Windows
vp6-run Calculator.vp6p                             # the console script
python -m vp6.runner Calculator.vp6p
```

Its `PROJECT` dict:

| Key | Meaning |
|---|---|
| `name` | the project name (also `App.Title`) |
| `type` | `"exe"` (GUI) or `"console"` |
| `startup` | a form class name, or `"Sub Main"` |
| `forms`, `modules` | file names relative to the project folder |
| `color_scheme` | `"system"`, `"light"`, `"dark"` or `"ide"` |

The IDE maintains this dict; code you add elsewhere in the file is kept. See
[architecture.md §6.2](architecture.md#62-project-files-vp6p) for the full
format.

## 10. Differences from Visual Basic 6

* **The language is Python.** `Me` is `self`, handlers are methods, and there
  are no `Dim` statements.
* **Units are pixels**, not twips. A form's `Width` and `Height` are its
  client area.
* **`ByRef` event arguments are return values** (see [§2](#2-events)).
* **Constants use the `vp` prefix** instead of `vb`.
* **Forms are classes.** Create instances explicitly (`frm = Form2();
  frm.Show()`); there are no implicit default instances.
* **Control arrays are `ControlArray` objects.** Elements are `self.cmd[i]`
  (or VB's `self.cmd(i)`); `Load` and `Unload` take the array and the Index
  (`Load(self.cmd, 5)` for `Load cmd(5)`).
* **Not implemented yet:** see [BACKLOG.md](../BACKLOG.md).
