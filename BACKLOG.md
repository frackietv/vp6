# VP6 backlog

- **[Self-hosting]** Step 1, the skeleton: a package project `vp6/studio/` (`Studio.vp6p`, `package = "vp6.studio"`, `command = "vp6-ide"`, Sub Main) that starts from the `vp6-ide` console script (`vp6.studio.__main__:main`, `run_package`) and from `python -m vp6.studio`; Main parses the IDE's command line as `mainwindow.main` does (`--help`, `--no-splash`, a project file), shows the splash (`App.ShowSplash`, the version in its colour) and an empty main MDIForm; package data for the project file and its pictures in `pyproject.toml`; a test that starts and unloads it offscreen; `docs/source-reference.md` gets a section for the studio. The rule from here on: the studio's forms and modules don't import PySide6; plain modules (`formfile`, `project`, `make`, `hotpatch`) are used as they are.
- **[Self-hosting]** Step 2, Qt-free logic out of the Qt IDE's modules, so both IDEs share it: the pure parts of `outline.py` (`outline`, `item_path_at`, `sorted_outline`), `findreplace.py` (`SearchOptions`, `compile_pattern`, `find_in`, `replacement`, project-wide search over texts), `menueditor.py` (`MenuEntry`, `entries_from`, `validate`, `menu_defs`), `objectbrowser.py` (`vp6_library`, `project_library`, `search`), `claude.py` and `codex.py` (sessions, transcripts, auth parsing, the protocols' messages) and `debugger.py` (`describe`, `same_file`) moved to modules without Qt imports (e.g. `vp6/ide/logic/`), the Qt IDE importing them from there; a test that importing them doesn't import PySide6.
- **[Self-hosting]** Step 3, the IDE's pictures and theme: `ide/icons.py` (toolbar, menu and Toolbox icons) and `ide/chrome.py` (the designer's window frames) as studio modules drawing into Pictures with the graphics methods (`RGBA`, `RoundRect`, `GraphicsPath`, `LinearGradient`, `DrawPath`), dark variants for the menus; the theme (`ide/theme.py`'s ThemeManager) on `App.ColorScheme`, `App.Style` and SaveSetting/GetSetting, the code colours and font kept per theme; a test comparing a few icons with the Qt IDE's (pixel tolerance).
- **[Self-hosting]** Step 4, the main window: `frmMain` (MDIForm, `ViewMode` tabs as View > Tabbed Documents sets it) with the Qt IDE's menus (File, Edit, View, Project, Format, Run, Debug, Tools, Help; menu `Picture`s, the theme menu as a `Group`), the toolbar and status bar; DockPanels for the Toolbox, Project, Properties, Immediate, Output, Terminal, Debug, Claude and Codex (tabbed and split as now, hidden ones out of the bottom tab group), the layout kept with `SaveLayout`/`LoadLayout`; window geometry and recent projects in settings; commands left disabled until their step.
- **[Self-hosting]** Step 5, projects and documents: a Qt-free `Document` (path, text, modified, kind, breakpoints as line marks) and the studio's open/save/close of projects and files; New Project (a form with the templates by category, samples, `create_project`, the Location by `ShowFolder`), Open, recent projects, Save, Save As (`copy_project`), Project Properties (a form, Package and Command included); files changed on disk read again (FileWatcher, `AppActivate`; only the changed span replaced, undoable); unsaved changes asked about when closing.
- **[Self-hosting]** Step 6, the Project panel: a TreeView of the project's groups (`Project.tree()`) with the file kinds' icons; Add Form / MDI Form / Splash / User Control / Module / Group, Rename, Delete, drag and drop between groups (`Project.move`), a PopupMenu, View Code / View Object, the unique file names `_import_names` keeps (not needed in a package project).
- **[Self-hosting]** Step 7, the code window: an MDI child form per file with a CodeBox (Python highlighting, line numbers, the theme's font and colours), the object and procedure lists (double-clicking a control writes its event handler), completion (CodeBox's list, filled by the code window's `complete`), Find and Replace (a form; the current file, the selection or the whole project, Find All into the Output window), Go To Line, comment/uncomment, the Outline window (TreeView over `outline()`), F1 on the word at the caret.
- **[Self-hosting]** Step 8, the form designer: an MDI child form per form or user control with a DesignerView (the form's region rewritten from its definition on every change, `formfile.replace_region`, undo as text), the designer's frame from step 3, the Format menu (align, make same size, centre, order, Lock Controls), the Menu Editor (a form over the shared menu logic), user controls loaded as types (`load_user_control` with the project's module names), View Code from a double click.
- **[Self-hosting]** Step 9, the Toolbox and Properties window: the Toolbox from `ControlTypes`/`ControlCategories`/`ControlInfo` (icons, the list view, grouped by category, the sort orders, the panel's width per view, user controls), the drop of a tool on the DesignerView; the Properties window as a FlexGrid property grid (object list, Alphabetic and Categorized with outline rows, the editors by property kind, the description pane), bound to the designer's selection, the project (`ProjectTarget`'s properties) or a file's (Name).
- **[Self-hosting]** Step 10, running: Start, Break, End and Restart through a Process (`Environment` with the IDE scheme and debugger variables, `Arguments` from the project's Arguments), the Immediate window (the program's output and input for console programs, statements run in break mode), the Output window, the Terminal window (a Terminal control in a DockPanel), Make Executable and Build Wheel (vp6-make in a Process, its output in the Output window).
- **[Self-hosting]** Step 11, the debugger: DebugSession on a Winsock listening on localhost (JSON lines with the debug agent), breakpoints from the code windows' marks (enabled or not, F9), Step Into/Over/Out, the current statement marked in its code window, the Debug panel (Watches in a FlexGrid, the Call Stack choosing the frame, the Breakpoints list), Edit and Continue (pending changes applied with the agent's `apply`), run-time errors opening the code at their line.
- **[Self-hosting]** Step 12, help and browsing: the Object Browser (a form over the shared library logic: classes, members, search, the description), the Help menu and F1 (`ShowHelp` at the context's page), About (a form with the logo Picture), the Kitchen Sink and samples opened from the Help menu.
- **[Self-hosting]** Step 13, Claude and Codex: their panels (login, sessions: New, Open, Rename, Delete) and chat windows (MDI children with MarkdownBoxes for the answers, tool questions answered Allow / Always Allow / Deny, modes, Stop, resumed sessions), `claude -p` and `codex app-server` in Processes with the shared protocol code; modified files saved before each message, changed ones read again.
- **[Self-hosting]** Step 14, parity and the switch: the Qt IDE's tests run against the studio where they apply (a `tests/test_studio_*.py` per step), screenshots of both IDEs compared for each window, the gaps found turned into `[Controls]` or `[Self-hosting]` items; then the `vp6` command starts the studio, the Qt IDE stays as `vp6 --classic` for one version and is removed after, CLAUDE.md and the docs describing the studio.
